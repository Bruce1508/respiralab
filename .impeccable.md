# Impeccable Design Context — RespiraLab

## Design Context

### Users
Primary: Hack Canada 2026 judges doing a live walkthrough of the Streamlit demo in a few minutes — need instant visual credibility and clarity, not deep reading time. Secondary: researchers/clinicians who may later inspect the repo and demo closely and care more about correctness/limitations than aesthetics.

### Brand Personality
Rigorous/precise, clinical/instrument-grade, approachable/curious. Matches the existing README tagline: "Built with curiosity, measured with restraint." The UI should feel like a well-calibrated lab instrument, not a vendor dashboard — confident about what it measures, explicit about what it doesn't know. Sound-event labels are never framed as diagnosis.

### Aesthetic Direction
Light mode is default (lab-bench / instrument-panel-on-paper), with a dark "scope" mode toggle (oscilloscope/monitor feel, not a palette-swap). Reference world: oscilloscopes, stethoscope diaphragms, spirometer printouts, lab-notebook grids, acoustic engineering plots.

**Anti-reference, explicit**: the current README badge row (cyan `#7dd3fc` / pink `#f472b6` / purple `#a78bfa` / rose `#fb7185` on near-black `#0b0d12`) is itself the generic "neon-on-dark AI palette" the design-skill guidance warns against. Don't carry that combination into the app UI as-is — it reads as templated, not chosen for this subject.

Avoid generically: glassmorphism, gradient text on metrics, generic rounded-card grids, sparkline-as-decoration, hero-metric-with-gradient-accent template, bounce/elastic easing.

### Design Principles
1. Every visual choice should read as measurement, not decoration — waveform/spectrogram rendering, probability output, and disclaimers are the content; chrome stays quiet.
2. Uncertainty is shown, not hidden — the `exploratory_window` vs `annotated_cycle` distinction and the "not a diagnostic device" warning get equal visual weight to the main result, never demoted to muted fine print.
3. One signature instrument-world element carries the personality (e.g. a custom scope/spectrogram treatment); everything else stays restrained, grid-disciplined, typographically plain.
4. Dark "scope" mode is a real second instrument state, not a color-token swap — and must avoid neon cyan/purple glow clichés.
5. Must work for a judge skimming in ~90 seconds AND a reviewer reading closely later — front-load result + disclaimer, progressively disclose detail (cycle-bounds input, spectrogram internals).
